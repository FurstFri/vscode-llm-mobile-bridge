# Установка — пошагово

Инструкция для человека, который просто хочет, чтобы заработало.
Читать сверху вниз, ничего не пропускать.

**Что получится в итоге:** на телефоне видны все чаты Claude Code и Codex
с компьютера, в них можно писать, и они отвечают.

---

## 0. Что нужно иметь

На компьютере (Windows):

- **VS Code** — уже стоит, раз вы это читаете;
- **Claude Code** и/или **Codex** — те, чьи чаты хотите видеть. Если стоит
  только один, второй просто будет с пустым списком;
- телефон на **Android 8.0** или новее.

Ничего дополнительно ставить (Node.js, Docker) для базового варианта **не нужно**.

---

## 1. Скачать два файла

Открыть страницу релизов:

**https://github.com/FurstFri/vscode-llm-mobile-bridge/releases/latest**

Внизу, в разделе **Assets**, скачать:

| Файл | Куда |
|---|---|
| `llm-mobile-bridge.vsix` | на компьютер |
| `llm-mobile-bridge-debug.apk` | на телефон |

> APK можно скачать прямо на телефоне, открыв ту же ссылку в браузере телефона.

---

## 2. Установить расширение в VS Code

**Способ мышкой (проще):**

1. В VS Code слева нажать значок **Extensions** (квадратики) или `Ctrl+Shift+X`.
2. Вверху панели нажать **«…»** (три точки).
3. Выбрать **Install from VSIX…**.
4. Указать скачанный `llm-mobile-bridge.vsix` → **Установить**.
5. **Перезагрузить окно**: `Ctrl+Shift+P` → напечатать `Reload Window` → Enter.

**Способ командой** (PowerShell, если файл лежит в «Загрузках»):

```powershell
code --install-extension "$env:USERPROFILE\Downloads\llm-mobile-bridge.vsix" --force
```

После этого **обязательно перезагрузить окно VS Code**.

**Как понять, что установилось:** слева в вертикальной панели значков
появится иконка **LLM Bridge**. Нажать на неё — увидите «Шлюз запущен ·
порт 8765» и списки чатов Claude Code и Codex.

> Если панель пустая или пишет «There is no data provider registered» —
> смотрите раздел «Если что-то не работает» в конце.

---

## 3. Установить приложение на телефон

1. Открыть скачанный `llm-mobile-bridge-debug.apk` на телефоне.
2. Android спросит разрешение ставить из этого источника — разрешить
   (**Настройки → Установка неизвестных приложений** → браузер/файлы → включить).
3. Установить, открыть приложение. Появится экран с полем для пейринга.

---

## 4. Выбрать, как телефон будет видеть компьютер

Есть два варианта. **Выберите один.**

| | Вариант А: дома, по кабелю USB | Вариант Б: откуда угодно, через сервер |
|---|---|---|
| Что нужно | кабель USB, `adb` на компьютере | свой сервер с доменом и HTTPS |
| Где работает | только когда телефон подключён к ПК | из любой сети, по мобильному интернету |
| Сложность | проще | нужен один раз настроить сервер |

Если у вас уже настроен домен (`wss://llmmb.parumatov.com`) — вам **вариант Б**.

---

### Вариант А — по USB-кабелю

1. На компьютере в настройках VS Code (`Ctrl+,` → искать `llmMobileBridge`)
   поставить **Mobile Url** = `ws://127.0.0.1:8765`, а **Relay Url** оставить
   **пустым**.
2. Подключить телефон кабелем, включить на нём «Отладку по USB».
3. Выполнить в PowerShell:

   ```powershell
   adb reverse tcp:8765 tcp:8765
   ```

4. Перейти к шагу 5 (пейринг).

> Команду `adb reverse` нужно повторять после каждого переподключения кабеля.

---

### Вариант Б — через свой сервер (работает везде)

На сервере поднимается «ретранслятор» — он ничего не хранит и не читает
переписку, только соединяет телефон с вашим компьютером.

1. На сервере создать стек (Dockge / docker compose) с таким файлом:

   ```yaml
   services:
     relay:
       image: ghcr.io/furstfri/vscode-llm-mobile-bridge:latest
       pull_policy: always
       restart: unless-stopped
       environment:
         RELAY_HOST: 0.0.0.0
         RELAY_PORT: 8765
       ports:
         - "127.0.0.1:8765:8765"
   ```

2. Настроить обратный прокси (nginx / Caddy / Traefik) так, чтобы домен
   `llmmb.example.com` вёл на `127.0.0.1:8765` **с поддержкой WebSocket**
   (заголовки `Upgrade` и `Connection`). Без этого связь не установится.

3. В VS Code (`Ctrl+,` → `llmMobileBridge`) заполнить **Relay Url**:

   ```
   wss://llmmb.example.com
   ```

4. Перезагрузить окно VS Code. В статус-баре внизу появится
   **«LLM Bridge: local+relay»** — значит, компьютер подключился к серверу.

5. Перейти к шагу 5 (пейринг).

**Обновление сервера в будущем:** просто перезапустить стек — образ
`:latest` подтянется сам. Конфиги менять не нужно.

---

## 5. Связать телефон с компьютером (пейринг)

1. В VS Code открыть панель **LLM Bridge** (иконка слева).
2. Нажать **«Скопировать пейринг для телефона»**.
   *(То же самое: `Ctrl+Shift+P` → `LLM Mobile Bridge: Copy Pairing Payload`.)*
3. Передать скопированный текст на телефон любым способом — например,
   отправить себе в мессенджер.
4. В приложении вставить этот текст в поле и нажать **«Подключить»**.

Готово. Сверху появится «Подключено», ниже — вкладки **CLAUDE CODE** и
**CODEX** со списком чатов.

> Текст пейринга — это ключ доступа к вашим чатам. Не публикуйте его.
> Если он куда-то утёк: в панели нажать **«Отключить все устройства»** —
> старый ключ перестанет работать, и нужно будет спарить телефон заново.

---

## 5.1. Несколько компьютеров (в том числе Remote-SSH)

Телефон умеет держать связь **сразу с несколькими машинами** — например, с
домашним ПК и с рабочим сервером, к которому вы подключаетесь по Remote-SSH.

Расширение показывает чаты той машины, **где оно запущено**:

| Окно VS Code | Чьи чаты видны |
|---|---|
| обычное, локальное | вашего компьютера |
| подключено по Remote-SSH | того сервера |

Чтобы добавить вторую машину:

1. Установить расширение **на этой машине**. В Remote-SSH окне: панель
   Extensions → у расширения LLM Bridge нажать **Install in SSH: имя-сервера**.
2. Задать там настройку **Relay Url** (тот же домен) — в Remote-окне настройки
   пишутся в раздел **Remote [SSH: …]**.
3. Полезно задать **Host Name** — понятное имя («Домашний ПК», «prod»),
   иначе будет показано системное имя машины.
4. В этом окне нажать **«Скопировать пейринг для телефона»**.
5. В приложении на экране со списком чатов нажать **«+ Компьютер»** и вставить
   новый пейринг.

Теперь в списке чатов видны сессии обеих машин, у каждой строки указано, с
какой она машины. «Новый чат» тоже отдельный для каждой машины.

Один ретранслятор обслуживает сколько угодно машин — он различает их по
токену. Ставить второй сервер не нужно.

---

## 6. Как пользоваться

- **Свайп влево/вправо** — переключение между Claude Code и Codex.
- **Тап по чату** — открыть переписку (открывается на последнем сообщении).
- **Поле внизу** — написать сообщение агенту, стрелка «↑» — отправить.
- **«+ Новый чат»** вверху списка — начать новую беседу с телефона.
- **Чипы над кнопкой отправки** — выбрать модель и уровень размышления
  для этого сообщения.
- Серые строчки «Размышления» и вызовы инструментов **раскрываются тапом**.

## 7. Если что-то не работает

### Панель в VS Code пустая / «There is no data provider registered»

Скорее всего установились две копии расширения — они конфликтуют.
Проверить в PowerShell:

```powershell
code --list-extensions | Select-String "llm-mobile-bridge"
```

Правильная строка одна: `furstfri.vscode-llm-mobile-bridge`.
Всё остальное (например, `furstfri.vscode-llm-mobile-bridge`) — удалить:

```powershell
code --uninstall-extension furstfri.vscode-llm-mobile-bridge
```

Затем поставить VSIX заново и **перезагрузить окно**.

### «The request envelope is invalid» при создании нового чата

Ретранслятор на сервере устарел — старая версия не знает про новые чаты.
Перезапустить стек на сервере (образ `:latest` подтянется сам):

```bash
docker compose pull && docker compose up -d
```

Отправка в **существующие** чаты при этом работает и на старом сервере.

### Открыто несколько окон VS Code

Шлюз держит только одно окно (порт занят). Остальные окна показывают внизу
**«LLM Bridge: another window»** — это нормально, они подхватят шлюз сами,
если главное окно закроется.

### В Remote-SSH окне не видно чатов сервера

Расширение должно быть установлено **на самом сервере**: панель Extensions →
у LLM Bridge нажать **Install in SSH: имя-сервера**. Затем задать там
**Relay Url** (в разделе настроек **Remote [SSH: …]**) и добавить этот
пейринг в приложении кнопкой **«+ Компьютер»** — см. раздел 5.1.

### Сообщения с телефона не доходят

Открыть в VS Code: меню **View → Output**, в списке справа выбрать
**LLM Mobile Bridge**. Там по каждой отправке будет строка:

- `Turn completed (claude)` — всё хорошо;
- `Turn failed (claude): <причина>` — причина написана прямо там.

Частые причины:

| Что написано | Что делать |
|---|---|
| `Native CLI binary … not found` | Обновиться до v0.3.4 или новее |
| `disabled in settings` | Включить настройку **Allow Sending Messages** |
| `Сессия занята другим устройством` | Дождаться окончания хода в VS Code |

### Агент пишет «Edit file …?» и останавливается

С телефона подтвердить правку нечем. Открыть настройки (`Ctrl+,` →
`llmMobileBridge`) и поставить **Claude Permission Mode**:

- `acceptEdits` — разрешить правку файлов (рекомендуется);
- `bypassPermissions` — разрешить вообще всё, включая команды в терминале
  (быстро, но рискованно для запуска вслепую).

### Телефон отваливается после блокировки экрана

Так и должно быть — соединение рвётся, но приложение переподключается само
при включении экрана (v0.3.5 и новее). Если висит «Не подключено» —
нажать **«Переподключить»**.

### Чатов не видно вообще

- Проверить, что вверху написано **«Подключено»**;
- нажать **«Обновить»**;
- проверить настройку **Session Scope**: `all` — чаты всех проектов,
  `workspace` — только текущей папки.

### Не устанавливается APK

Android блокирует установку из неизвестных источников. Разрешить в
**Настройки → Приложения → Специальный доступ → Установка неизвестных
приложений** для браузера или файлового менеджера.

## 8. Обновление на новую версию

1. Скачать свежие `.vsix` и `.apk` со [страницы релизов](https://github.com/FurstFri/vscode-llm-mobile-bridge/releases/latest).
2. Расширение — поставить поверх (`Install from VSIX…` или команда с `--force`),
   **перезагрузить окно VS Code**.
3. APK — установить поверх, данные пейринга сохранятся.
4. Если используете сервер (вариант Б) — перезапустить стек на сервере.

Заново связывать телефон не нужно.

---

## 9. Настройки — что есть

`Ctrl+,` → в поиске набрать `llmMobileBridge`.

| Настройка | Что делает | По умолчанию |
|---|---|---|
| **Auto Start** | запускать шлюз при старте VS Code | вкл |
| **Port** | порт локального шлюза | 8765 |
| **Relay Url** | адрес сервера-ретранслятора (вариант Б) | пусто |
| **Host Name** | как эта машина называется на телефоне | имя компьютера |
| **Mobile Url** | адрес для телефона без ретранслятора (вариант А) | `ws://10.0.2.2:8765` |
| **Session Scope** | `all` — все проекты, `workspace` — только открытая папка | all |
| **Session Limit** | сколько чатов показывать на провайдера | 100 |
| **Allow Sending Messages** | разрешить отправку с телефона | вкл |
| **Claude Permission Mode** | права для ходов с телефона | default |
| **Claude Executable** | путь к `claude.exe`, если не нашёлся сам | пусто |

## 10. Собрать самому (не обязательно)

Нужны Node.js 20+ и JDK 17.

```powershell
npm.cmd install
npm.cmd test
npm.cmd run package:vsix          # → artifacts\llm-mobile-bridge.vsix
cd android
.\gradlew.bat assembleDebug       # → app\build\outputs\apk\debug\app-debug.apk
```
