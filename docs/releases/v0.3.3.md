# v0.3.3

## Fix: Claude sends from the phone

Long Claude turns were being killed by a self-conflict: the turn itself
writes into the session file, the phone's 5-second snapshot poll observed
the changed revision while the writer lease was held, and the registry
flagged the session as externally conflicted. Every following `turn.start`
was rejected with a `session.conflict` event the app didn't even display —
sends appeared to vanish. Short Codex turns usually slipped through, which
is why "ChatGPT works, Claude doesn't".

- Revision changes observed while our own writer holds the lease no longer
  create a conflict; the session stays `busy` and returns to `idle` on
  release.
- Provider turn failures now carry the real error in `detail`, and the
  gateway logs turn lifecycle to the "LLM Mobile Bridge" output channel.
- The Android app shows conflict events and error details instead of
  swallowing them.
