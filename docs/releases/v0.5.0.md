# v0.5.0

## Several machines at once — PC and Remote-SSH servers together

v0.4.1 forced the extension to run locally (`extensionKind: ui`), which cut
off Remote-SSH windows entirely. That was the wrong trade: the fix belongs in
the app, not in where the extension runs.

- **The extension follows the workspace again** (`extensionKind:
  ["workspace", "ui"]`). A Remote-SSH window serves that server's Claude Code
  and Codex sessions; a local window serves the PC's. Install it on every
  machine you want to reach.
- **The phone pairs with several machines.** Pairings are stored as a list
  (still Keystore-encrypted), one WebSocket per machine, and the session list
  merges all of them. Existing single-machine pairings are migrated on first
  launch — no need to pair again.
- **Every machine has a name.** The pairing payload now carries `name`
  (the hostname, or `llmMobileBridge.hostName` if set). Session rows, the
  chat header and the "new chat" rows show it whenever more than one machine
  is paired.
- **Per-machine routing.** Snapshots, turns and new chats go to the machine
  the session belongs to; a session ref is only unique within its machine.
- **Adding and removing machines** from the app: "+ Компьютер" on the session
  list, "убрать" next to each machine on the pairing screen.

## Notes

- Each machine needs its own relay URL setting (`llmMobileBridge.relayUrl`)
  and its own pairing token — in a Remote-SSH window set it in the
  **Remote** settings scope.
- One relay serves any number of machines: it routes by pairing token.
- `session.new` still requires the v0.4.0+ relay image on the server.
