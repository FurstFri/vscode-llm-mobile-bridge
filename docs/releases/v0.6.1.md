# v0.6.1

## Fix: sending broke whenever the gateway restarted

Session references were random UUIDs held only in memory, so every gateway
restart invalidated every reference the phone knew. Reading survived —
the phone re-lists sessions every 15 seconds and picks up fresh references —
but a `turn.start` carrying an older reference found nothing in the registry
and was answered as "read-only", with no log line to show for it. Restarts
were frequent: a VSIX update, a manual stop, or two windows trading the port.

- **References are now derived, not random**: an HMAC of the provider and its
  session id, keyed by a per-machine secret in `SecretStorage`. They survive
  restarts, stay opaque, and differ between machines.
- **An unknown reference reloads the session list and retries** instead of
  failing, so a reference from a previous process still works.
- A genuinely unknown reference now answers `UNKNOWN_SESSION` ("обновите
  список чатов") and is logged, rather than masquerading as a read-only
  session.

## Gateway control

Stopping the gateway from the panel or the command palette now sticks — the
30-second health check no longer restarts what you deliberately stopped. It
still recovers from crashes, updates and freed ports.

## Note on pairing tokens

One machine has one token, shared by every window and project on it: the
relay routes a phone to a machine by that token, and each machine keeps its
own token in `SecretStorage`. Windows on the same machine cooperate over the
port instead — one serves, the others stand by.
