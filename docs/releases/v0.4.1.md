# v0.4.1

## Remote windows and multiple VS Code windows

- **The extension is now `extensionKind: ui`.** In a Remote-SSH window it
  would otherwise run on the remote host, read *that* machine's `~/.claude`
  and `~/.codex`, and register with the relay under a different pairing
  token — so the phone either saw the wrong sessions or nothing at all. It
  now always runs on the machine holding the sessions.
- **Remote workspace paths are ignored.** A `vscode-remote://` folder path
  is meaningless to the local session stores; `sessionScope: workspace` no
  longer filters everything out, and new chats fall back to the home
  directory instead of a non-existent remote path.
- **A second VS Code window no longer errors out.** When port 8765 is
  already served by another window, this one goes to standby
  ("LLM Bridge: another window") and takes over automatically within 15
  seconds if that window closes.

## CI

Pushing a commit and its tag together started two identical image builds;
the racing pushes tripped GHCR's secondary rate limit and one build failed
with a 403. Both image workflows now serialize per commit.

## Note for relay users

`session.new` (new chats from the phone) requires the **v0.4.0 relay image
or newer** on the server. An older relay answers "The request envelope is
invalid" — restart the stack so `:latest` is pulled.
