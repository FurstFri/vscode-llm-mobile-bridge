# v0.3.0

## Highlights

- **Relay mode: server as a dumb pipe, sessions stay on the PC.** The
  standalone relay service is back and integrated with the current gateway.
  The relay (`node dist/relay-server.js`, image
  `ghcr.io/furstfri/vscode-llm-mobile-bridge`) stores nothing and needs no
  tokens in its config: the VS Code extension keeps an outbound WSS
  connection to it (`llmMobileBridge.relayUrl`), registers with the pairing
  token, and the phone is routed to the matching host by presenting the same
  token. All session data, transcripts, and message sending run on the PC —
  including the new `turn.start` write path, which is now forwarded through
  the relay.
- **Pairing through the relay.** With `relayUrl` set, "Copy Pairing Payload"
  emits the relay domain instead of a local address, so the phone works from
  any network without `adb reverse` or tunnels to the PC.
- The relay image is published on every `main` push and release tag as
  `ghcr.io/furstfri/vscode-llm-mobile-bridge:latest`, so an existing server
  stack with `pull_policy: always` only needs a container restart.

## Artifacts
