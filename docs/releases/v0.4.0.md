# v0.4.0

## New chats, model choice and thinking control — for both providers

- **Start a new chat from the phone.** Each provider tab has a "Новый чат"
  row; the first message creates a real provider session (Claude via the
  Agent SDK, Codex via `thread/start`) in the VS Code workspace folder and
  streams the answer. The gateway registers it behind an opaque ref, so it
  appears in the session list like any other chat.
- **Model selection per turn.** A composer chip picks the model — Opus /
  Sonnet / Haiku for Claude, GPT-5.1 Codex Max / Codex / GPT-5.1 for Codex —
  or leaves the provider default.
- **Thinking control per turn.** A second chip sets the effort level
  (`low` … `max`), or turns extended thinking off. For Claude this maps to
  `effort` + adaptive thinking (`thinking: {type: "disabled"}` when off);
  for Codex it is passed to `turn/start`.
- The mobile protocol gains `session.new` and optional `model` / `effort`
  fields on `turn.start`; the relay forwards both.

## Notes

- Model and thinking selections apply to the turn you send; they are not
  persisted per session yet.
- Codex model/effort values are forwarded to `turn/start` as-is — if a
  build of the Codex app-server ignores them, the thread's configured model
  is used.
