# v0.9.0

## Find the provider CLIs on Linux and remote hosts

On a Remote-SSH host both providers reported **zero models** and every turn
failed, while the session list worked perfectly — reading transcripts needs
no CLI, everything else does.

The executable lookup was written for a Windows desktop: it searched
`~/.vscode/extensions` for `claude.exe` and for Codex only ever looked at
`bin/windows-x86_64/codex.exe`. A Linux remote keeps its extensions in
`~/.vscode-server/extensions` and ships unsuffixed binaries, so nothing was
ever found.

- Lookup moved to a shared, platform-aware module: PATH (with the Windows
  suffixes), `~/.local/bin`, then every extension root — `.vscode`,
  `.vscode-server`, and their Insiders variants — with the right binary name.
- Codex's per-platform `bin/<platform>/` folder is now scanned instead of
  assuming `windows-x86_64`.
- When a model list still comes back empty, the reason travels to the phone
  in `provider.status.note` instead of showing a silently empty picker.
