# v0.13.0

## The two forks are one project again

Work on this project had been going on in two folders at once. `Chat_Extension`
carried the history the phone build came from (v0.12.0); `G:\vs_code\vscode-llm-mobile-bridge`
was a stale clone from before a history rewrite, edited for a day on top of an
older tree. The two were not fast-forwardable and neither was a superset.

This release keeps the v0.12.0 tree as the base — modes, agent questions, the
`PreToolUse` hook, permission modes, stable session references, the standalone
gateway daemon — and ports the work that only existed in the other copy on top
of it. Everything the two had built independently is now in one history; the
other copy contributes nothing further.

## Pairing by QR code

The status bar entry now opens a small menu whose first item is **Показать QR
для телефона**, and the app's pairing screen gains **Сканировать QR**. No more
mailing yourself a JSON blob.

The encoder is a dependency-free ISO/IEC 18004 implementation (byte mode,
versions 1–40, Reed–Solomon, mask selection) that renders to inline SVG; the
webview runs no scripts and loads nothing remote, so the token never leaves the
workstation. The phone side uses `com.journeyapps:zxing-android-embedded`,
which needs no Play Services.

## A pairing has a stable identity

The pairing payload now carries a `connectionId` and a `label`. Re-pairing the
same machine **updates** its entry in the app instead of adding a second one for
the same host, and the token is stored under a key derived from that id.

Pairings made before this release keep working: the old flat secret is carried
across on first use, and the app still matches an entry by URL and token when a
machine sends no id.

## Finding a machine whose address changed

With `llmMobileBridge.discovery` on (the default) the extension answers UDP
broadcast probes with the machine name and gateway port — **never the token**.
The app's **Найти в сети** button repairs the address of an already paired
machine from that answer. Answering a probe therefore cannot pair a device that
was never given the credential, and only a plain `ws://` pairing is repaired: a
`wss://` relay pairing is left alone so a LAN address cannot downgrade it.

## Questions reach the phone with the app closed

The connections moved out of the Activity into a process-wide repository driven
by a `dataSync` foreground service. Closing the app no longer drops the sockets:
a question or an approval raised on the workstation raises a high-priority
notification, and tapping it opens that conversation. A prompt answered on the
phone, or timed out on the machine, clears its notification.

## Sessions stop showing as decades old

Providers report "last updated" as epoch milliseconds, epoch seconds or ISO-8601
text depending on the build, and reading one as another is what rendered a chat
as «20650 дн назад». Every timestamp entering the gateway now goes through one
parser that understands all three shapes and returns nothing for an implausible
value, so a client renders no date instead of 1970. The Codex session revision
keeps using the raw value as a change token, or an ISO-8601 build would collapse
it to a constant.

## Updating from inside the app

The app is installed from a GitHub release rather than a store, so it now checks
the releases API, compares the tag against its own version component by
component (0.11.0 correctly beats 0.9.0), downloads the APK to its cache and
hands it to the platform installer through a `FileProvider`.

## Notes

Item 1 of the merge plan proposed per-window pairing tokens and per-window
ports. That fits a gateway scoped to one workspace folder; this gateway serves
the machine's whole session store, and exactly one window hosts it while the
others stand by and take over if it closes. Per-window ports would have replaced
that with N gateways serving identical session lists. The stable identity and
the scoped token key were adopted; the fixed port and the standby/takeover
behaviour were kept.
