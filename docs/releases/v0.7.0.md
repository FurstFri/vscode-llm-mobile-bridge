# v0.7.0

## Renamed publisher and Android package

The extension publisher and the Android application id no longer carry the
previous internal name:

| | Before | Now |
|---|---|---|
| VS Code extension id | `furstfri.vscode-llm-mobile-bridge` | `furstfri.vscode-llm-mobile-bridge` |
| Android application id | `com.furstfri.llmmobilebridge` | `com.furstfri.llmmobilebridge` |

Release assets from earlier versions were removed, since the old names were
compiled into them.

## What this means when updating

Both identifiers are how the platforms tell applications apart, so this
release installs alongside the old one rather than over it:

1. **VS Code** — uninstall the old extension, then install the new VSIX:

   ```powershell
   code --uninstall-extension furstfri.vscode-llm-mobile-bridge
   code --install-extension llm-mobile-bridge.vsix --force
   ```

   Settings are kept (they are keyed by `llmMobileBridge.*`, not by
   publisher). The pairing token and session-reference secret live in
   `SecretStorage` under the extension id, so a **new token is generated** —
   re-copy the pairing payload to the phone.

2. **Android** — uninstall the old app first; the new one is a separate
   package and cannot upgrade it in place. Paired machines have to be added
   again.
