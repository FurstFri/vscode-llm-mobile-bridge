# v0.8.0

## Approve tool use from the phone

Until now a Claude turn started from the phone had no way to answer a
permission prompt: `default` denied everything that needed approval and
`acceptEdits` still stalled on shell commands. The prompt is now forwarded to
the phone instead.

- The adapter installs a `canUseTool` handler that emits an
  `approval.request` event and waits; the app shows a card with the tool
  name, the command or path it is about to touch, and **Разрешить / Отклонить**.
- The answer travels back as a new `approval.respond` request (the relay
  forwards it) and resolves the prompt inside the running turn — no restart,
  no lost context.
- Unanswered prompts are denied after 5 minutes, and an interrupted turn
  releases them, so a forgotten notification cannot wedge a session.
- New default for `llmMobileBridge.claudePermissionMode`: **`askOnPhone`**.
  The previous values still work — `default` (deny), `acceptEdits`,
  `bypassPermissions` (allow everything, no prompts).

## Note for Remote-SSH machines

Each machine runs its own copy of the extension with its own settings scope.
After updating, install the new VSIX **on the remote host too** (Extensions →
*Install in SSH: host*) and set `relayUrl` there in the **Remote** settings —
an older copy still hands out session references that this gateway no longer
honours, which looks exactly like "messages do not arrive".
