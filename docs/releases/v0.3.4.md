# v0.3.4

## Fix: Claude sends failed in the installed extension

The Agent SDK locates its native `claude` binary through an optional
npm package next to itself — but the packaged extension ships a single
bundle with no `node_modules`, so every phone-initiated Claude turn failed
with "Native CLI binary for win32-x64 not found" (visible in the output
channel since v0.3.3).

- The Claude adapter now resolves the installed CLI itself and passes it
  via `pathToClaudeCodeExecutable`. Search order: the new
  `llmMobileBridge.claudeExecutable` setting → `CLAUDE_BIN` → `PATH` →
  `~/.local/bin` → the Claude Code VS Code extension's bundled binary.
- Verified end to end with the bundled adapter running from a directory
  without `node_modules`.

## Artifacts

- `artifacts/llm-mobile-bridge.vsix` — VS Code extension (the fix)
- `artifacts/llm-mobile-bridge-debug.apk` — Android client (unchanged)
