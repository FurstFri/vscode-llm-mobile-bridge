# v0.6.0

## Real model lists and usage limits — from the providers themselves

The model names shipped in v0.4.0 were invented (`gpt-5.1-codex-max` and
friends never existed). Nothing is hardcoded any more: both lists come from
the provider on the machine that serves the session.

- **Models** — Codex answers `model/list` (e.g. GPT-5.6-Sol, GPT-5.6-Terra
  with their descriptions), Claude answers `supportedModels()` (Default,
  Sonnet, Haiku, Opus 1M …). Hidden entries are skipped.
- **Thinking levels follow the chosen model.** Each model reports which
  effort levels it accepts, so the picker only offers what will work;
  choosing a model resets the level. Claude keeps the extra "off" option,
  which maps to `thinking: {type: "disabled"}`.
- **Usage limits are shown.** Codex reports them on demand
  (`account/rateLimits/read`: percentage used, window, reset time, plan);
  Claude reports them as a stream event during a turn, so the gateway keeps
  the newest one seen — until the first answer it shows "Появится после
  первого ответа". The app draws a thin bar that turns amber past 70% and
  red past 90%, per machine and per provider.
- New `provider.status` request in the mobile protocol (relay forwards it);
  the app asks on connect, on refresh and after every turn.

## Gateway resilience

Installing a new VSIX disposes the running extension, and VS Code does not
re-activate it until the window reloads — so the phone silently lost the
machine after every update. The extension now re-checks every 30 seconds and
starts the gateway whenever nobody is serving the port.
